# ANVL Audit — 2026-05-17

Full-stack read-only audit of the ANVL Athletics storefront + admin CMS on branch
`cms_merge`. Findings cover security, component reusability, redundancy,
performance / bundle size, responsiveness / accessibility / smoothness, and
SOLID / scalability / maintainability. A consolidated, prioritized **task list**
lives at the bottom of this doc — every task references the finding(s) that
motivate it.

This audit did **not** modify any application code. Use it to plan the next
round of CMS-merge prompts.

---

## 1. Executive summary

The codebase has a coherent **3-layer architecture** (storefront UI → feature
hooks/services → runtime clients) and several mature patterns:
SSR-safe `createRuntimeClients({ isServer })`, `useSyncExternalStore` snapshot
wrappers for localStorage, parallel route loaders, lazy-imported marketing
acts, `Drawer` focus trap, Lenis/GSAP gated by viewport + reduced-motion in the
hero, `JsonLd` `<` escaping, sanitized active-drop palette CSS, and a Zod-guarded
drops persistence path.

The **biggest risks before the next milestone** are:

1. **Admin auth is purely client-side** — `localStorage` session + `VITE_*`
   credentials bundled into client JS. Already documented as temporary debt, but
   blocks any hosted admin.
2. **Several admin editor files exceed 800–1200 lines** and mix UI, validation,
   persistence orchestration, and domain helpers. Hard to onboard, hard to
   refactor safely, and they leak into the storefront bundle graph because the
   CMS read-path lives under `features/admin/**`.
3. **No automated tests** — `vitest` is wired but `src/` contains zero
   `*.test.*` files. Solo handoff risk is high.
4. **Bundle splitting is partial.** Only `/admin/products/` uses
   `lazyRouteComponent`; the rest of the admin (drop editor, product editor,
   website layout, theme, settings, media) is statically imported through
   `routeTree.gen.ts`. `manualChunks` only splits gsap/lenis/framer-motion.
5. **Persistence validation drift** — drops use a strict Zod parse, but
   products, website layout, global brand, and legacy landing CMS reads merge
   raw JSON with light structural checks only.
6. **CMS-driven `<a href>` and `<img src>` values are not URL-scheme-allowlisted**
   (e.g. PDP 3D model link, footer socials, hero secondary CTA). Low risk while
   the admin is a single trusted operator; medium-high once a real backend or
   second user exists.
7. **GSAP/ScrollTrigger acts still run on mobile** (Oath stamp, Drop reveal,
   Pieces grid, Materials marquee, Waitlist) — only `prefers-reduced-motion` is
   gated, not `max-width: 767px`. `HeroForgeSequence` already has the correct
   pattern; the other acts need parity.
8. **`Modal` lacks focus trap / Escape / programmatic focus**, unlike `Drawer`.
   Multiple admin destructive flows depend on it.
9. **`scripts/repatch-admin-route-tree.mjs` is operational debt** — it runs on
   every `pnpm dev` / `pnpm build` / `pnpm typecheck` to inject
   `/admin/media` + `/admin/settings` because the TanStack Router codegen
   doesn't pick them up.

None of these are show-stoppers for the documented "demo / local CMS" phase, but
all should be tracked before public launch — and most of them get cheaper to fix
the sooner they're addressed.

## 2. Security findings

Cross-references `docs/performance-accessibility-security.md` and
`docs/technical-debt.md`. Severity is calibrated to the **demo / local CMS**
phase; some "Critical" findings are already documented as temporary debt.

### Critical

- **SEC-01 — Admin "session" is forgeable client JSON.** `readAdminSession()`
  (`src/features/admin/auth/adminAuth.storage.ts`) only checks that `username`
  and `loggedInAt` are strings; an attacker who can write `localStorage`
  (extension, XSS elsewhere, shared device) gets full admin access without
  knowing the password. Fix: real server-side session (HttpOnly + Secure cookie
  + CSRF) and server-enforced admin APIs.
- **SEC-02 — Admin password is bundled into client JS** via `VITE_ANVL_ADMIN_*`
  (`adminAuth.storage.ts` lines 8–17). Vite inlines `import.meta.env.VITE_*`;
  anyone can recover credentials from the production bundle or source map. Fix:
  remove all secrets from the client; use server auth (BFF, IdP, etc.).

Both findings are already called out in `docs/technical-debt.md` as expected
compromises; they are listed here to ensure they remain blockers before any
hosted admin instance.

### High

- **SEC-03 — `/admin` is client-gated only.** `ProtectedAdminRoute` is a pure
  `useEffect` redirect; there is no `beforeLoad` auth and no server middleware.
  Combined with SEC-01/02, an attacker can render `/admin/*` content even
  without valid credentials (and then mutate `localStorage` to satisfy the
  guard).
- **SEC-04 — CMS-driven `<a href>` values are not URL-scheme-allowlisted.**
  - PDP 3D-model link: `src/routes/shop/$slug.tsx` ~190–201.
  - Hero secondary CTA: `src/features/marketing/components/HeroForgeSequence.tsx`
    ~333–348 (CMS `secondaryCta.href` rendered with raw `<a>`).
  - Footer socials: `src/shared/components/layout/SiteFooter.tsx` ~106–120.
  Need a shared `sanitizeHref(url, { allowRelative: true, schemes: ['https','http','mailto','tel'] })`
  used at every CMS `href` boundary.
- **SEC-05 — Storefront demo credentials are hard-coded and printed on the
  sign-in page** (`src/app/config/accountMock.ts` `DEMO_EMAIL`/`DEMO_PASSWORD`;
  rendered in `src/routes/auth/sign-in.tsx`). Acceptable for labeled local
  demo; must be removed before any public-facing environment.
- **SEC-06 — `.env.example` ships a realistic-looking password (`Test123@`).**
  Encourages copying into real envs. Replace with `changeme` + warning.
- **SEC-07 — Persistence schema-bypass for products / website layout /
  global brand / legacy landing CMS.** `drops.service.ts` uses
  `persistedDropSchema` correctly, but `products.service.ts`,
  `websiteLayout.service.ts`, `globalBrand.service.ts`, and the legacy
  `landingCms.storage.ts` only do `JSON.parse` + light checks + `as` casts. A
  tampered `localStorage` blob can drive admin and storefront state.
- **SEC-08 — SSR uses seed adapters, browser uses localStorage adapters,
  producing different first-render content.** This is documented architecture
  but means crawlers / view-source / share previews see seed-only content while
  shoppers see admin-edited content. Acceptable for solo local CMS; problematic
  for SEO and "what did I publish?" auditing once shared.

### Medium

- **SEC-09 — No CSP / HSTS / `frame-ancestors` headers.** `vite.config.ts` has
  no header plugin. Acceptable while local-only; required for production.
- **SEC-10 — Cart persists in `localStorage` via Zustand `persist`** with names,
  prices, and image URLs (`src/features/cart/store/cart.store.ts`). Any XSS or
  malicious extension can read/modify. Migrate to server-side cart with backend.
- **SEC-11 — Account session is a `sessionStorage` customer id pointer
  (`anvl.storefrontAccount.customerId`).** Trivial to spoof in the demo because
  `mockAccountClient.getCustomerProfile` trusts the id. Replace with HttpOnly
  cookies + server session.
- **SEC-12 — Admin login has no throttling / lockout / CAPTCHA** (n/a until
  real auth lands).
- **SEC-13 — Sign-up reveals existing emails** via the
  `STOREFRONT_ACCOUNT_EMAIL_TAKEN` error (`src/routes/auth/sign-up.tsx` ~59–62).
  Forgot-password already returns a uniform success message — mirror that
  pattern on sign-up.
- **SEC-14 — Drop preview iframe has no `sandbox` attribute and uses
  `doc.head.innerHTML = ''`** (`DropEditorLivePreview.tsx`). The React subtree
  still runs in the parent context (intentional); add a documented threat
  model + a minimal `sandbox` allowlist where compatible.
- **SEC-15 — `absoluteImageUrl` preserves `http://` URLs in SEO / JSON-LD**
  (`src/shared/components/seo/structuredData.ts` ~4–7). Mixed-content risk on
  HTTPS. Normalize to HTTPS, or warn in admin on save.
- **SEC-16 — `DropActsBuilderPanel.bootstrapFromLanding` parses arbitrary JSON
  paste without Zod** (~834–839). Use the same `persistedLandingActSchema` as
  storage.
- **SEC-17 — Storage merges use object spread of untrusted JSON
  (`websiteLayout`, `globalBrand`).** Adopt `z.strict()` + validated output to
  avoid future `__proto__` / `constructor` polution footguns when migrations
  add fields.
- **SEC-18 — Future CSRF.** When mutations move to a real backend, plan for
  double-submit cookies or SameSite=Strict + same-origin patterns.

### Low

- **SEC-19 — `stripAngleBracketTags` is only applied in
  `DropActivePageView`.** Apply on save (schema transform) so every text field
  in the CMS is clean.
- **SEC-20 — `MediaPickerField` URL input accepts any string.** Use
  `isValidUrlOrPath` from `drops.editor.validation.ts` before `onChange`.
- **SEC-21 — File-pick validation checks MIME + size, not magic bytes.**
  Acceptable for the data-URL/local-storage demo; required server-side once
  uploads ship.
- **SEC-22 — `TanStackDevtools` is mounted in `__root.tsx` for every
  environment.** `@tanstack/devtools-vite` defaults to
  `removeDevtoolsOnBuild: true` (`node_modules/@tanstack/devtools-vite/dist/esm/plugin.js`),
  but belt-and-braces gate with `import.meta.env.DEV`.
- **SEC-23 — `package.json` pins several `@tanstack/*` packages to
  `"latest"`** (`react-devtools`, `react-router`, `react-router-devtools`,
  `react-start`, `react-router-ssr-query`). Non-reproducible installs +
  supply-chain drift. Pin exact versions.

### Positive controls (keep)

- `dropPaletteStyle.sanitizeCssValue` blocks `{}`, `<>`, `expression(`,
  `javascript:`, `@import` before `<style dangerouslySetInnerHTML>`.
- `JsonLd` escapes `<` to `\\u003c`.
- Drops persistence (`persistedDropSchema`) — model to emulate elsewhere.
- YouTube embeds normalize via `extractYoutubeVideoId`.
- Forgot-password uniform message reduces enumeration.
- Analytics mock logs only in `DEV`.

## 3. Performance, bundle size, runtime efficiency

### High impact

- **PERF-01 — All admin routes except `/admin/products/` are eagerly imported
  by `routeTree.gen.ts`.** Every visitor to the public storefront pays for the
  admin route component graph (drop editor, product editor, website layout,
  theme, settings, media, drop builder). Action: add
  `lazyRouteComponent(() => import(...))` to every admin route file.
- **PERF-02 — `DropActsBuilderPanel.tsx` (~1179 lines) is statically imported**
  by `DropLandingActsEditor` → `DropEditorRoute` → `routes/admin/drops/$dropId.tsx`.
  Wrap the panel in `React.lazy` + Suspense behind the Acts tab.
- **PERF-03 — Storefront imports `features/admin/**` runtime code**
  (`shop/$slug.tsx` pulls `products.service` and `products.mapper`;
  `drop/$slug.tsx` pulls `products.commerce`; `__root.tsx` pulls
  `dropPaletteStyle`; `PublicLandingActs` pulls `drops.actSequence`). Even with
  type-only imports erased, runtime imports drag admin-oriented modules into
  shared chunks. Move shared CMS-read code from `features/admin/**` to
  `features/cms/**` or `features/drops/**`; keep `features/admin/**` for
  admin-only UI + mutation.
- **PERF-04 — `readDropsArray()` does `getItem` + `parseDropsPayload` on every
  call** (`drops.service.ts`). Multiple synchronous reads per update multiply
  work. Keep a module-level parsed cache invalidated by `subscribeDropsChange`.

### Medium impact

- **PERF-05 — `vite.config.ts` `manualChunks` only splits gsap / lenis /
  framer-motion.** Add chunks for `@tanstack/react-router*`,
  `@tanstack/react-query*`, `react-hook-form` + `@hookform/resolvers`, `zod`,
  `lucide-react`, `sonner` — tune after an analyzer run.
- **PERF-06 — Docs reference `pnpm analyze` but `package.json` has no
  `analyze` script.** Add `"analyze": "ANVL_ANALYZE=1 vite build"`.
- **PERF-07 — `defaultPreloadStaleTime: 0` with `defaultPreload: 'intent'`**
  (`src/router.tsx`) can cause duplicate loader work on hover/focus. Try a
  short non-zero stale time (e.g. 30s) and measure.
- **PERF-08 — Sequential awaits in route loaders.** `/drop/$slug` awaits
  `getActiveDrop` before SEO `Promise.all` (necessary for redirect, but the SEO
  parallel could start earlier on the happy path). `/shop/$slug` fetches
  product then related — parallelize if the API allows.
- **PERF-09 — Fonts use full `@fontsource` CSS imports for Manrope 400/500/600/700
  + Bebas 400** (`src/styles.css` lines 1–6) and `<head>` has no
  `<link rel="preload" as="font">`. Switch to subset/variable fonts and preload
  the 1–2 critical `woff2` files.
- **PERF-10 — CMS image URLs ship raw** — no `srcset`, `sizes`, width/height,
  or blur placeholder. Layout shifts + oversize bytes from arbitrary admin
  URLs. Plan an image CDN + enforce dimensions in CMS schema.
- **PERF-11 — Unused dependencies bloating install + dev surface.** Grep shows
  no imports for `@tanstack/react-table`, `@tanstack/react-virtual`,
  `@tanstack/react-query-devtools`, and `framer-motion` (the latter is only
  imported by `src/shared/components/motion/*` and `HeroSpinningMark.tsx`,
  neither of which is mounted anywhere). Either delete them or use them
  intentionally (e.g. virtualize the admin product/drop tables with
  `react-virtual`).
- **PERF-12 — Long lists are non-virtualized.** `/shop/index.tsx` maps over the
  whole catalog; admin product/drop lists are full DOM. Use
  `@tanstack/react-virtual` above ~50–100 rows.
- **PERF-13 — `ProductGallery` thumbnails / CMS `<img>` lack explicit
  width/height + `loading="lazy"` consistently.** Audit and standardize.

### Low impact

- **PERF-14 — `shop/index.tsx` `filterProps` `useMemo` deps drop `onPatch` /
  `onReset`.** Wrap handlers in `useCallback` or expand deps.
- **PERF-15 — Two reactivity strategies for drops** — `useAdminDropsListQuery`
  (TanStack Query) vs `useDropsList()` (`useSyncExternalStore`). Pick one to
  reduce subtle desync between admin list and editor.
- **PERF-16 — `TanStackDevtools` ships in `__root.tsx`.** Gate with
  `import.meta.env.DEV` for belt-and-braces alongside the Vite plugin.

### Positive controls

- Lenis + GSAP scroll loaded only on `min-width: 768px` + no reduced motion.
- `useLandingCms` / `useHomeProducts` use `useSyncExternalStore` snapshot
  cache — model to emulate.
- Most loaders are already parallel.
- `lucide-react` uses named imports (tree-shake-friendly).
- `vendor-gsap` / `vendor-lenis` / `vendor-framer-motion` manual chunks exist.

## 4. Component reusability & redundancy

### High-leverage consolidations

- **REU-01 — Admin form-field bypass.** `DropEditorRoute`,
  `DropLandingActsEditor`, `DropActsBuilderPanel`, and
  `routes/admin/products/-adminProductsIndex.tsx` all copy a local
  `const fieldClass = 'mt-1 w-full rounded-md border ...'` and use raw
  `<input>` / `<textarea>` + ad-hoc `FieldError` instead of `FormField` +
  `Input`/`Textarea`. Estimated 150–400 lines saved if a thin
  `AdminTextField` / `AdminTextarea` wrapper or `FormField`'s `variant="admin"`
  preset is introduced.
- **REU-02 — `ShopFiltersForm` uses raw `<input type="checkbox">` and
  `<select>`** instead of the shared `Checkbox` / `Select` primitives.
- **REU-03 — Datetime-local helpers duplicated.** `pad2` / `padDt` /
  `isoToDatetimeLocal` / `toDatetimeLocal` exist in three files
  (`DropEditorRoute.tsx`, `ProductEditorRoute.tsx`, `DropsAdminList.tsx`).
  Extract to `src/features/admin/lib/adminDatetime.ts`.
- **REU-04 — Primary product image helper duplicated.** `primaryListImage`
  (in `-adminProductsIndex.tsx`) and `primaryPreview` (in `ProductEditorRoute`)
  re-implement the same "first color → primary image → fallback alt" logic.
  Extract `getAdminProductHeroImage(product): { src, alt } | null`.
- **REU-05 — `*.storage.ts` modules duplicate scaffolding.**
  `drops.storage.ts`, `products.storage.ts`, `websiteLayout.storage.ts`,
  `globalBrand.storage.ts`, `landingCms.storage.ts` all repeat: `isBrowser`,
  `read*Raw`/`write*Raw`, EventTarget + `storage` event listener, `*_CHANGE_EVENT`.
  Extract `createLocalStorageChannel({ key, eventName })` + optional
  `createJsonStore<TSchema>({ key, schema, defaults, merge })`. Saves ~80–120
  lines and removes the variance that causes SEC-07.
- **REU-06 — Editor route patterns duplicated.** `DropEditorRoute` and
  `ProductEditorRoute` both implement: tab state, dirty tracking,
  `useSaveSuccessFlash`, confirm modals, datetime helpers, "back to list"
  chrome. Extract `useAdminEditorChrome({ backHref, title, onSave, ... })` and
  per-tab presentational components.
- **REU-07 — Marketing acts share GSAP scaffolding.** Six files under
  `src/features/marketing/components/*` all do `gsap.matchMedia` +
  `gsap.utils.toArray` + `gsap.set` initial + `timeline()`. Extract
  `useIndustrialScrollReveal({ scopeRef, buildTimeline, reducedMotionFallback })`
  — 80–150 lines saved and one place to enforce the mobile gate (cf.
  RESP-03).
- **REU-08 — `Skeleton` is exported but unused** (`src/shared/components/ui/Skeleton.tsx`
  is 3 lines and has zero call sites). Remove or implement.
- **REU-09 — `DropLoadingIndicator` is used but missing from the UI barrel
  (`index.ts`).** Add the export.

### Medium

- **REU-10 — Drop schemas exist in three shapes.** `features/drops/schemas/drop.schema.ts`
  (canonical zod), `features/admin/drops/drops.types.ts` (hand-written), and
  `features/admin/drops/drops.persistence.zod.ts` (persistence-shaped). Pick
  one source of truth per boundary and `z.infer` the rest.
- **REU-11 — Brand color tokens live in 3+ places.**
  `src/shared/constants/brand.ts` (`BRAND_COLORS`), `src/styles.css`
  (`--anvl-*` custom properties), and inline `#0B0B0C` literals in
  `products.defaults.ts`, `products.mapper.ts`, `products.mock.ts`,
  `dropPaletteStyle.ts`, `__root.tsx` `theme-color`. Pick a single palette
  module and re-export from there.
- **REU-12 — Defaults files embed many literal strings** that aren't derived
  from `BRAND` (`drops.defaults.ts`, `landingCms.defaults.ts`,
  `websiteLayout.defaults.ts`, `globalBrand.defaults.ts`, `products.defaults.ts`).
- **REU-13 — Admin product list reactivity** uses local `useState` in
  `-adminProductsIndex.tsx` while drops list uses `dropsListUi.store` Zustand.
  Pick one pattern.
- **REU-14 — Query keys are ad-hoc.** `useProducts` uses bare `['products']`
  while account / admin drops have factory objects. Adopt the factory pattern
  everywhere.

## 5. Responsiveness, a11y, smoothness

### High

- **RESP-01 — `Modal` lacks focus trap, programmatic focus, and Escape
  handling.** Only the backdrop is a button (`src/shared/components/ui/Modal.tsx`).
  Used by `routes/admin/settings.tsx`, `DropEditorRoute.tsx`, others. Wire
  `useDialogFocusTrap` (already used by `Drawer`) and add an `Escape` listener
  to the dialog.
- **RESP-02 — PDP sticky purchase bar covers content on mobile.** Bar is
  `fixed bottom-0 ... lg:hidden p-3` in `src/routes/shop/$slug.tsx` ~305–327
  with no `pb-[max(env(safe-area-inset-bottom),...)]` and no bottom spacer on
  the `Section`. Related-products + accordion can sit under it on notched
  phones.
- **RESP-03 — Marketing acts run rich GSAP/ScrollTrigger on mobile.**
  `OathStampSequence`, `DropRevealSection`, `PiecesGrid`, `MaterialsMarquee`,
  and `WaitlistSection` all only gate on `prefers-reduced-motion`. Mirror
  `HeroForgeSequence.tsx` (~83–91) which uses
  `(max-width: 767px), (prefers-reduced-motion: reduce)` to snap to final
  state. Centralize the matchMedia helper while you're at it (cf. REU-07).

### Medium

- **RESP-04 — Missing `focus-ring` on key storefront surfaces.**
  `ProductCard` `Link` (~39), `PiecesGrid` links (~174–238),
  `StickyHeader` desktop nav (~110–116) and announcement link (~69–81),
  `ProductGallery` thumbs (~33–42), `AdminSidebar` (~58–66).
- **RESP-05 — Touch targets below ~44 px.** `IconButton` (`h-10 w-10`),
  `ColorSwatch` (`h-9 w-9`), `Button size="sm"` (`h-9`, used by
  `QuantityStepper`), `DropsAdminList` status tabs `py-1.5` pills.
- **RESP-06 — Long-text overflow risk.** `ProductCard` title + price flex row
  (`ProductCard.tsx` ~59–68) lacks `min-w-0` + `truncate`/`break-words`;
  `routes/checkout/index.tsx` order lines (~184–191); `cart.tsx` heading
  (~46–52). Long CMS names blow the layout.
- **RESP-07 — iOS Safari zoom-on-focus.** `Input` / `Textarea` use `text-sm`
  (14 px). Use `text-base md:text-sm` to keep 16 px on mobile.
- **RESP-08 — `PiecesGrid` uses `grid-cols-3` even at 320 px.** Use
  `grid-cols-1 sm:grid-cols-3` (or similar) and re-test type at narrow
  widths.
- **RESP-09 — Hero titles `text-6xl` on small screens.** Routes `cart`,
  `checkout/index`, `shop/index`, `shop/$slug` use `text-6xl` without
  responsive downscaling; `DropActivePageView` already shows the correct
  pattern (`text-5xl sm:text-6xl`).
- **RESP-10 — `SiteFooter` newsletter is not in a `<form>`** (~97–103) and
  group labels use `<p>` instead of headings (~69–71).
- **RESP-11 — `Toaster` `position="top-right"` can overlap mobile chrome**
  (`AppProviders.tsx` ~21). Use responsive position or safe-area offsets.
- **RESP-12 — Encoding glitch** in `src/routes/shop/index.tsx` ~46 (`ΓÇö`
  mojibake instead of `—`).

### Low

- **RESP-13 — Settings modal title `<h3>` without preceding `<h2>` in dialog
  context** (`routes/admin/settings.tsx` ~76–78).
- **RESP-14 — `AccordionDisclosure` chevron span lacks `aria-hidden`** and
  `summary` lacks an explicit `focus-ring`.
- **RESP-15 — Admin editor density on tablets.** Drop/product editors stack
  but require heavy scroll + small toolbar targets below ~1024 px. Not
  broken, but not "comfortable."
- **RESP-16 — Loading states inconsistent.** Account routes show "Loading…"
  text; admin list shows "Loading drops…"; landing has a centered emblem.
  Adopt `Skeleton` blocks matching final layout where it matters.

### Positive controls (keep)

- `useLenisScroll` gates on `min-width: 768px` + reduced motion.
- `Drawer` implements focus trap + Escape + restore focus.
- `FormField` wires `role="alert"` for errors.
- Drop status pills include text labels, not color-only.
- `:root` `prefers-reduced-motion` rule shortens transitions globally.

## 6. SOLID, scalability, maintainability

### High

- **MAINT-01 — Oversized files.**
  - `src/features/admin/drops/DropActsBuilderPanel.tsx` (1179 L)
  - `src/features/admin/products/ProductEditorRoute.tsx` (988 L)
  - `src/features/admin/drops/DropEditorRoute.tsx` (972 L)
  - `src/features/admin/drops/DropLandingActsEditor.tsx` (850 L)
  - `src/routes/admin/website-layout.tsx` (732 L)
  - `src/features/admin/drops/DropsAdminList.tsx` (647 L)
  - `src/routes/admin/products/-adminProductsIndex.tsx` (628 L)

  Each mixes 5–8 responsibilities (route shell, draft state, validation,
  persistence orchestration, modals, domain helpers, presentation). Split per
  file using the pattern: `useXxxEditor()` hook + `XxxTab` presentational
  components + small helper module (`adminDatetime.ts`, `nature-fields/*.tsx`,
  etc.). See finding card per file for the suggested split.

- **MAINT-02 — Storefront / marketing depend on `features/admin/**`.**
  `src/routes/shop/$slug.tsx`, `src/routes/drop/$slug.tsx`,
  `src/features/products/hooks/useHomeProducts.ts`,
  `src/features/products/api/commerceClient.*.ts`,
  `src/features/marketing/public-landing/PublicLandingActs.tsx`,
  `src/routes/index.tsx`, `src/routes/__root.tsx`,
  `src/shared/components/ui/DropLoadingIndicator.tsx`,
  `src/app/providers/ActiveDropTheme*.tsx` all reach into
  `features/admin/**` for what is really "CMS-read" code. Move the shared
  CMS read-path to `features/cms/**` (or `features/drops/**` for drop-specific)
  and keep `features/admin/**` for admin UI + mutation only. Add an ESLint
  rule (`no-restricted-imports`) to block future leaks. Also addresses
  PERF-03.

- **MAINT-03 — `scripts/repatch-admin-route-tree.mjs` is fragile codegen
  surgery.** Runs on every `pnpm dev` / `build` / `typecheck` to inject
  `/admin/media` + `/admin/settings`. Fail-closed string-level patching. Fix
  the root cause in route layout / TanStack Router plugin config so the
  generator emits these routes; then delete the script.

- **MAINT-04 — `drops.service.ts` is a god service.** Imports
  `products.service`, `landingCms`, `websiteLayout`, `globalBrand`; also runs
  `resetAllLocalCmsKeys` and orchestrates cross-feature hydration. Extract
  `cmsKernel` / `localCmsFacade` for orchestration; keep `drops.service`
  drop-only. Also: `products.commerce.ts` imports `drops.service` →
  conceptual circularity.

- **MAINT-05 — No automated tests.** `pnpm test` exists, `vitest` is wired,
  but zero `*.test.*` files in `src/`. Add tests for: drops zod
  parse/migrate, products mapper, `composeLandingPageFromDrop`,
  `shopUrlSearch`, `seoMeta`, `sanitizeCssValue`, datetime helpers,
  storefront route loaders. Even ~10 critical-path tests are a meaningful
  safety net for a solo handoff.

## 8. How to use this audit

1. Open the **Phase A** tasks first — they're the safety net for everything
   else (tests + analyzer + error boundaries + version pinning).
2. **Phase B + C** can land in parallel — both reduce risk in the
   currently-deployed local-CMS phase without blocking work.
3. **Phase D → E → F → G** is the bulk of the structural cleanup; D unlocks
   meaningful bundle wins in G.
4. **Phase H** is highest user-facing leverage per hour; do it any time after A.
5. **Phase J** is tracked here so it doesn't get lost when the backend lands,
   but it can wait until the Medusa work in `docs/backend-medusa-roadmap.md`
   is on the table.

Cross-reference IDs (e.g. `SEC-04`, `PERF-02`, `MAINT-01`) in PR titles and
commit messages so future agents can trace tasks back to this audit.

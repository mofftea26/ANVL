## Deferred work

### Phase D (folder boundary)

**Goal:** Public and shared code should not import implementation details from `features/admin/**`; CMS contracts should live under `features/cms/**` (and drop read-models under `features/drops/**` where appropriate).

**Why deferred:** `landingCms.types.ts` depends on `PublicLandingAct` from admin acts types; `cmsClient.localStorage.ts` already sits in `features/cms/api` but still calls `drops.service`. Unwinding this cleanly requires a coordinated move of types + facades without breaking lazy routes or doubling modules.

**Next step:** Introduce `features/cms/facades/*` that re-export narrow read-only APIs; move shared **types** upward first; then switch storefront imports file-by-file.

### Phase E (maintainability / file size)

**Goal:** Bring editor files under the ~300/500 line guidance in `.cursor/rules/40-solid-maintainability.mdc`.

**Why deferred:** High churn risk; best done as dedicated PRs per editor with QA on preview + persistence.

### Phase F (DX)

**Goal:** Datetime helpers, image helpers, shared scroll hooks, query-key conventions, dependency cleanup.

**Why deferred:** Non-blocking for audit closure; schedule as small incremental PRs.

### Phase I (tooling)

**Current state:** `scripts/repatch-admin-route-tree.mjs` patches TanStack-generated `routeTree.gen.ts` so `/admin/media` and `/admin/settings` stay registered after codegen.

**Why deferred:** Upstream Start/Router may eventually emit these routes without a patch; investigate `routeFileIgnorePattern` / plugin options when upgrading `@tanstack/react-start`.

**Done in stack:** Vitest files under `routes/**/__tests__` use the `-` prefix so the route scanner ignores them.

### Phase J (launch hardening)

**Goal:** Server-side auth, HTTP-only sessions, CSP, HSTS, rate limiting, upload validation, CSRF policy.

**Why deferred:** Requires deployment target and backend; tracked as **hosted-demo / production blockers** in `docs/technical-debt.md`.
